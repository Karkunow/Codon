# Тести еквівалентності original.py ↔ twirl.codon

`original.py` (Python + Qiskit) є еталоном; `twirl.codon` зібрано в `libtwirl.dylib`.
Тести перевіряють, що бібліотека дає ті самі flips, ті самі twirled-схеми (кожна
інструкція, фаза, clbits, shots) і ті самі об'єднані ймовірності (допуск 1e-12).

## Як запускати

```bash
cd /Users/slava.karkunov/Projects/Codon
.venv/bin/python -I tests/gen_cases.py   # генерує tests/cases.json з виходами original.py (~1 с)
python3 -I tests/check_codon.py          # ганяє cases.json через libtwirl.dylib, без qiskit (~0,3 с)
python3 -I tests/check_codon.py 152 166  # лише вказані id кейсів
TWIRL_LIB=/шлях/до/іншої.dylib python3 -I tests/check_codon.py   # інша збірка (мутанти)
```

Код виходу 0 тоді й лише тоді, коли всі кейси збігаються. Рядок невдачі називає кейс,
n, k, закінчення схем і поле: `flips: rows [...]`, `twirled[i] (task t, instance j): op 3: ...`,
`merged[t]: prob of 0x5: ...`, `preprocess rc 4 (unsupported_op), expected ok`.

`cases.json` детермінований (`MASTER_SEED`), 220 кейсів, ~2,9 МБ (twirled-схеми займають
більшість; 150 випадкових кейсів дають 2,2 МБ). Кейси 0–151 генеруються тим самим потоком rng, що й раніше (`make_case` і цикл у `main` не змінені; побайтове порівняння зі старим файлом не робилось, він перезаписаний).

## Таблиця мутацій

Мутовані копії `twirl.codon` і їхні dylib лежать у `tests/mutants/` (збірка: команда з
`build.sh` з `-o tests/mutants/<назва>.dylib`). Усі результати нижче отримано запуском
`TWIRL_LIB=tests/mutants/<назва>.dylib python3 -I tests/check_codon.py` 2026-11-20; справжня
бібліотека на тому ж `cases.json` дає 220/220.

| мутація | спіймано | кейси, що впали |
|---|---|---|
| прибрати `and _shares_qubit(dag, node, p)` у `_final_ops` (`no_shares_qubit`) | так, 205/220 | 152–164, 166, 215 (у twirled на один barrier менше; 166: rc 0 замість 4) |
| `n > 63` → `n > 64` (`n_gt_64`) | так | 172 |
| `num_instances < 1` → `< 0` (`k_lt_0`) | так | 168 |
| прибрати перевірку збігу num_qubits (`no_mismatch_check`) | так | 170, 171 |
| прибрати `if shots == 0` (`no_empty_check`) | так | процес падає з `ZeroDivisionError` Codon на кейсі 173 (не рядок FAIL, а аварійне завершення; код виходу 1) |
| flips лише для q < 32 (`flips_low32`) | так | 178–180, 187, 189, 195, 197, 203, 205, 211, 213 |
| маска `1 << (q % 32)` (`mask_mod32`) | так | ті самі 11 кейсів, поле `merged` |
| бар'єр ніколи не фінальний (`- 1 > 0` → `> 0`, `barrier_never_final`) | так, 104/220 | 116 кейсів: 114 випадкових (0–149), 183, 215 |
| версія `libqiskit` ≠ версії заголовка (`version_check`) | так, 0/234 у режимах 1 і 2 | усі (код 8) |
| таблиця гейтів зсунута на 1 (`gate_table_shift`) | так, 18/234 (режим 1); 21/234 + 98 розбіжностей (режим 2) | більшість |
| без перевірки непідставлених параметрів (`no_symbolic_check`) | так: процес аварійно завершується (panic у libqiskit, код виходу 134) | 232–233 |
| обернений ключ сортування швидкого шляху (`order_reversed`) | так: 214/234 (режим 1); режим 2 — 234/234 завдяки відкату на DAG, але 21 розбіжність → код виходу 1 | `order_stress`, випадкові |
| без відкату для операцій без кубітів (`no_zero_qubit_guard`) | так: 233/234 (режим 1), 1 розбіжність (режим 2) | 220 |
| режим 2 не порівнює (`verify_trusts_fast`) | сам по собі ні (швидкий шлях правильний, нічого ловити); разом з `order_reversed` у режимі 2 — 214/234 | — |
| раніше (попередня сесія): без `/ k` у postprocess; barrier завжди фінальний; без barrier у `measure_all`; маска MSB-first; не копіюється global phase; фінальні бар'єри лишаються | так (за звітом попередньої сесії, у цій сесії не повторено; dylib не збережено) | випадкові кейси 0–149 |

Чому `shared_clbit` убиває мутацію: мутант відвідує попередник по clbit-дротові (раніший
measure в той самий clbit), той уже фінальний, але його квантові попередники кладуться в
стек ще раз, і лічильник бар'єра зменшується на один більше, ніж у бар'єра наступників.
Бар'єр, який мав лишитись (після нього є гейт на кубіті n−1), помилково видаляється.
Мінімальний кейс 152: `barrier(0,1,2); measure(0,0); measure(1,0); x(2)`.

## Прогалини (не покрито)

- Параметри `inf`/`nan`: порівняння з допуском їх не підтримує.
- Операції поза gate/barrier/reset/measure (delay, store тощо) → очікуваний код 4, кейсів немає.
- Seed < 0 або ≥ 2⁶³, k > 129, n > 20 з випадковим тілом (широкі кейси мають 1–63 гейти h/x).
- Кілька класичних регістрів у вхідній схемі; measure одного кубіта двічі в різні clbits.
- Мутант `no_empty_check` виявляється лише аварійним завершенням, не читабельним FAIL.
