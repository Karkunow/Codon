(кейси `permuted`, `interleaved` проходять).

## Теоретична підлога

Після B лишається чиста робота libqiskit: копія + X + barrier + measures (0.29 мс на 40 копій, C) і
перебудова bare (0.04 мс, C). Разом 0.33 мс = виміряні 0.32–0.34 мс для B. Далі без зміни API libqiskit
(вставка гейтів перед готовим хвостом, `compose` тощо) прискорювати нічого: qk_circuit_copy,
qk_circuit_gate і qk_circuit_measure це і є мінімум.

## Рекомендація

Портувати в `twirl.codon` обидві зміни з `perf/twirl_fast2.codon`:

1. `_add_meas_register` один раз на bare + `_measure_tail` на копію (−10 %, тривіально, вихід ідентичний).
2. `_remove_final_fast` перед `qk_circuit_to_dag` з відкатом на DAG (разом 2.1× на бенчмарку, 1.6–2.1× на
   інших розмірах). Ризик: таблиця `_GATE_NAMES` привʼязана до порядку enum StandardGate у Qiskit; при
   невідомому імені код відкочується на DAG, тож помилки не буде, лише втрата швидкості. Варто додати
   в тести перевірку таблиці проти `QkGate_*` з `types.h`.

Очікуваний виграш: preprocess 0.69 → 0.32 мс на базовому розмірі (2.1×), postprocess без змін.
Codon-бік оптимізувати не треба: виміряно, що він коштує ≈ 0.
